# ADR-0003: Echo + pedantigoecho + pedantigo v2

**Status:** Accepted (2026-08-22)

## Context

The Rust HTTP surface (`gateway-http-anthropic`) is built on a stack of
routing, request binding, and schema validation. The Go port needs an
equivalent: an HTTP router, a way to bind request bodies into typed
structs, and a validation layer that can turn a bad field into a
structured `invalid_request_error` with a field path in the message (see
[ADR-0005](ADR-0005.md)).

## Decision

- **Router:** `echo` v4 — mature, minimal middleware surface, and the
  central `HTTPErrorHandler` hook it exposes is exactly the seam needed to
  serialize every error into the Anthropic error shape in one place
  instead of at every handler.
- **Binder:** `pedantigoecho` v2, installed as `e.Binder =
  pedantigoecho.NewBinder()`, covering POST/PUT/PATCH body binding.
- **Validation:** `pedantigo` v2's `validate` struct tag, with each
  request struct registered explicitly:
  `var _ = validator.Register(validator.New[T]())` (this panics at
  startup if a struct is malformed, which is the intended fail-fast
  behavior — a broken validator registration should never reach
  production).

GET/DELETE routes take query parameters, which the binder doesn't cover;
those structs are validated explicitly after `c.Bind`.

## Consequences

- Validation errors have one code path to the wire format, not one per
  handler — reduces the chance of a handler forgetting to map a bind
  failure into the Anthropic shape.
- Every request DTO needs its registration line, or validation silently
  no-ops for that type until the panic is hit at first use — this is a
  sharp edge worth flagging in code review for new DTOs.

## Alternatives considered

- **`gin` / `chi` + hand-rolled validation** — rejected: `pedantigo` and
  `pedantigoecho` already exist and are proven in `smritea-cloud`, so
  reusing them avoids re-solving "typed body binding with field-path
  validation errors" from scratch.
